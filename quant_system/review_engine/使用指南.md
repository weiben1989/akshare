## 📊 系统功能

### 完整的分析流程

```
数据获取 → 因子计算 → 四维度评分 → 资产配置 → 报告生成
   ↓           ↓            ↓            ↓           ↓
AkShare    多周期趋势    综合打分      仓位建议    Markdown
8个接口    EMA/斜率    0-100分     风格/行业      +JSON
```

### 核心功能模块

#### 1. 数据层（providers/）

**8个真实数据接口**：

| 接口 | 数据内容 | 用途 |
|------|---------|------|
| fetch_indices | 四大指数（上证/深成/创业板/沪深300） | 市场表现 |
| fetch_market_amount | 两市成交额 | 流动性指标 |
| fetch_market_breadth | 涨跌家数、涨跌停 | 市场宽度 |
| fetch_northbound | 北向资金流入 | 外资动向 |
| fetch_etf_flows | ETF资金流向（5个分组） | 资金偏好 |
| fetch_margin | 融资融券余额 | 杠杆水平 |
| fetch_industry_data | 行业数据聚合 | 行业轮动 |
| fetch_macro_data | PMI、PPI宏观数据 | 宏观环境 |

**数据存储**：
- SQLite数据库（9张表）：结构化数据查询
- Parquet文件：时序数据高效存储

#### 2. 计算层（core/）

**多周期因子**（factors.py）：
- 3个窗口：5日、10日、30日
- 3个指标：EMA（趋势）、斜率（方向）、Z-score（相对位置）
- 趋势标签：多周期共振上行/下行、短期反弹长期下行等

**四维度评分**（scoring.py）：

| 维度 | 权重 | 核心指标 | 含义 |
|------|------|---------|------|
| 宏观 | 25% | PMI、PPI、GDP | 经济基本面 |
| 流动性 | 35% | M2、融资、ETF | 资金充裕度 |
| 风险偏好 | 20% | 换手率、涨跌停 | 情绪热度 |
| 动量 | 20% | 指数动量、宽度 | 趋势强度 |

得分范围：0-100，综合得分映射到市场状态和建议仓位。

**资产配置**（allocation.py）：

| 功能 | 输出 |
|------|------|
| 仓位配置 | 权益%、债券%、现金% |
| 风格偏好 | 成长/价值/平衡 |
| 市值配置 | 大盘%、中盘%、小盘% |
| 行业配置 | 超配/标配/低配行业列表 |

#### 3. 报告层（reporting/）

**三段式报告**：

1. **利好因素** ✅
   - 自动提取得分≥60的维度
   - 发现配置型机会的行业

2. **利空因素** ⚠️
   - 自动提取得分<50的维度
   - 识别过度拥挤的行业

3. **结论与建议** 💡
   - 仓位配置：具体百分比
   - 风格偏好：成长/价值倾向
   - 行业配置：超配3个+低配3个
   - 操作建议：逐步建仓/减仓/观望

## 🔧 高级用法

### 1. 自定义配置

编辑 `config/config.yaml`：

```yaml
# 修改评分权重
score_weights:
  macro: 0.30      # 提高宏观权重
  liquidity: 0.30
  riskon: 0.20
  momentum: 0.20

# 修改窗口期
windows: [3, 7, 21]  # 改为3日、7日、21日

# 修改行业轮动阈值
industry_rotation:
  strength_weight: 0.7  # 更看重强度
  crowding_weight: 0.3
```

### 2. 命令行参数

```bash
# 使用自定义配置文件
python run_daily.py --config /path/to/config.yaml

# 只生成报告不保存
python run_daily.py --no-save

# 组合使用
python run_daily.py --date 2025-10-20 --config my_config.yaml
```

### 3. 编程调用

```python
from review_engine.run_daily import DailyReviewEngine
from pathlib import Path

# 创建引擎
engine = DailyReviewEngine(Path('config/config.yaml'))

# 运行复盘
result = engine.run(date='2025-10-21', save_report=True)

# 获取数据
composite_score = result['scores']['composite']['total_score']
position = result['allocation']['position']['equity_position']

print(f"综合得分: {composite_score}")
print(f"建议仓位: {position}%")
```

### 4. 数据库查询

```bash
# 连接SQLite数据库
sqlite3 data/review.sqlite

# 查询最近10天的指数数据
SELECT date, name, close, change_pct
FROM indices
WHERE name = '上证指数'
ORDER BY date DESC
LIMIT 10;

# 查询融资融券趋势
SELECT date, balance, buy_amount
FROM margin
ORDER BY date DESC
LIMIT 30;

# 查询北向资金流入
SELECT date, net_inflow
FROM northbound
ORDER BY date DESC
LIMIT 20;
```

## 🚀 性能优化建议

### 1. 数据缓存

首次运行会下载所有数据，后续运行会复用缓存：

```bash
# 首次运行（慢，10-30分钟）
python run_daily.py --date 2025-10-21

# 再次运行同一天（快，<1秒）
python run_daily.py --date 2025-10-21  # 从数据库读取
```

### 2. 批量分析

分析多个日期：

```bash
# 分析最近7天
for i in {0..6}; do
    date=$(date -d "-$i days" +%Y-%m-%d)
    python run_daily.py --date $date
done
```

### 3. 定时任务

设置每日自动复盘（crontab）：

```bash
# 每天收盘后16:00运行
0 16 * * 1-5 cd ~/Documents/akshare/quant_system/review_engine && python run_daily.py
```

## 🐛 常见问题

### Q1: 数据获取失败怎么办？

**A**: 检查网络连接和AkShare版本

```bash
# 更新AkShare到最新版
pip install --upgrade akshare

# 查看详细错误日志
tail -f review_engine.log
```

### Q2: 报告中某些数据为空？

**A**: 可能是当天数据未公布

```bash
# 查看数据库中有哪些日期的数据
sqlite3 data/review.sqlite "SELECT DISTINCT date FROM indices ORDER BY date DESC LIMIT 10;"
```

### Q3: 如何修改评分权重？

**A**: 编辑 `config/config.yaml` 中的 `score_weights` 部分，确保四个权重加起来等于1。

### Q4: 可以分析港股或美股吗？

**A**: 当前只支持A股。如需扩展，需修改 `providers/akshare_provider.py` 添加相应接口。

## 📚 架构说明

### 模块关系

```
run_daily.py (主程序)
    ↓
    ├─ providers/akshare_provider.py (数据获取)
    │   ↓
    │   data/review.sqlite (存储)
    │   data/parquet/ (时序)
    ↓
    ├─ core/factors.py (因子计算)
    ├─ core/scoring.py (评分系统)
    ├─ core/allocation.py (配置决策)
    ↓
    └─ reporting/renderer.py (报告生成)
        ↓
        output/reports/ (输出)
```

### 设计理念

1. **模块化**：每个模块独立可测
2. **可配置**：通过YAML灵活调整
3. **可扩展**：易于添加新数据源和指标
4. **零虚拟数据**：严格遵守真实数据原则
